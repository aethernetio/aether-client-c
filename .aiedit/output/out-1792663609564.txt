<h3>Отчёт: подход DataInOut vs builder в emitter.c</h3>

<h4>1. Обычные методы (emit_api_source_ctx, ~строки 5834–5983)</h4>
<p>Обычные методы используют <b>DataInOut</b> через поле <code>api->out</code> структуры <code>%s_%s_remote_t</code>. Фрагмент генерации (строки 5940–5981):</p>
<pre>aether_status_t %s_%s_%s(
    %s_%s_remote_t *api, ...) {

    if (api == NULL ||
        api-&gt;send == NULL ||
        api-&gt;out == NULL) {
        return AETHER_ERR_ARGUMENT;
    }

    aether_data_out_t *out = api-&gt;out;
    if (!aether_data_out_write_byte(out, %uu)) {
        return AETHER_ERR_OVERFLOW;
    }
    ...
    return api-&gt;send(
        api-&gt;send_ctx,
        api-&gt;out-&gt;data,
        api-&gt;out-&gt;pos);
}</pre>
<p>Здесь <code>api->out</code> — это <code>aether_data_out_t*</code>, переданный извне (внутри remote-объекта). Никакого локального <code>aether_data_out_t out</code> (по значению) здесь не создаётся.</p>

<h4>2. Stream-методы (builder-подход)</h4>
<p>Stream-методы генерируются в <code>emit_stream_builder_definitions_for_api_ctx</code> (строки 4346–4578). Они принимают <code>builder_stream</code> (указатель на stream-тип, напр. <code>csa_login_stream_t *builder_stream</code>) и используют локальную <code>aether_data_out_t out</code>. Ключевой фрагмент (строки 4512–4556):</p>
<pre>aether_status_t %s_%s_%s(
    %s_t *builder_stream, ...) {

    if (builder_stream == NULL ||
        builder_stream-&gt;length &gt; builder_stream-&gt;capacity) {
        return AETHER_ERR_ARGUMENT;
    }

    if (builder_stream-&gt;capacity &gt; 0u &amp;&amp;
        builder_stream-&gt;data == NULL) {
        return AETHER_ERR_ARGUMENT;
    }

    size_t remaining =
        builder_stream-&gt;capacity - builder_stream-&gt;length;

    if (remaining == 0u) {
        return AETHER_ERR_OVERFLOW;
    }

    %s_stream_commit_t commit = {
        &amp;builder_stream-&gt;length,
        remaining
    };

    aether_data_out_t out;
    aether_data_out_init(&amp;out, builder_stream-&gt;data + builder_stream-&gt;length, remaining);

    %s_%s_remote_t remote = {
        &amp;commit,
        %s_stream_commit,
        &amp;out
    };

    return %s_%s_%s(
        &amp;remote, ...);
}</pre>
<p>Аналогично для flush-функции (строки 4461–4496) — там тоже создаётся <code>aether_data_out_t out</code> поверх буфера <code>builder_stream</code>.</p>

<h4>3. Использование aether_data_out_init / aether_data_in_init</h4>
<ul>
<li><code>aether_data_out_init</code> встречается <b>2 раза</b> — оба в stream-builder коде (строки 4487, 4556). В обоих случаях инициализируется <b>локальная</b> <code>aether_data_out_t out</code> поверх участка памяти из <code>builder_stream</code>.</li>
<li><code>aether_data_in_t</code> встречается в других контекстах (для десериализации ответов), но <b>не</b> в stream-генерации. Для stream-методов ответа (<code>in</code>) не создаётся — только <code>out</code>.</li>
</ul>

<h4>4. emit_stream_builder_definitions_for_api_ctx (строки 4346–4578)</h4>
<p>Генерирует <b>по одной функции на каждый метод</b> для stream-типа. Для каждого метода создаётся:</p>
<ul>
<li>если метод <b>collapsible</b> — функция <code>&lt;stream&gt;_&lt;api&gt;_&lt;method&gt;</code> (принимает <code>builder_stream</code> + collapse-контекст) и отдельно <code>_flush</code>-версия. Обе используют <code>builder_stream</code> для записи через <code>aether_data_out_t out</code>.</li>
<li>если метод <b>обычный</b> (не collapsible) — функция <code>&lt;stream&gt;_&lt;api&gt;_&lt;method&gt;</code> аналогично.</li>
</ul>
<p>То есть stream использует builder, но уже переведён на <code>aether_data_out_t</code> для записи данных.</p>

<h4>5. Итог</h4>
<table border="1" cellpadding="5">
<tr><th>Подход</th><th>Обычные методы</th><th>Stream-методы</th></tr>
<tr><td>Механизм</td><td><b>DataInOut</b> (<code>api-&gt;out</code> — <code>aether_data_out_t*</code>)</td><td><b>Builder</b> (<code>builder_stream</code> + <code>stream_commit</code>)</td></tr>
<tr><td>aether_data_out_t</td><td>Через указатель <code>api-&gt;out</code></td><td>Локальная переменная <code>out</code>, инициализированная поверх <code>builder_stream-&gt;data</code></td></tr>
<tr><td>aether_data_in_t</td><td>Не используется в генерации</td><td>Не используется в stream</td></tr>
</table>
<p><b>Вывод:</b> Текущий emitter.c для <b>обычных методов</b> полностью использует DataInOut (aether_data_out_t через <code>api-&gt;out</code>). Для <b>stream-методов</b> по-прежнему применяется <b>builder-подход</b> (<code>builder_stream</code> + <code>stream_commit</code>), но уже <b>внутри builder'а данные пишутся через <code>aether_data_out_t</code></b> — то есть переход начался, но только на уровне буферизации выходных данных. Полного перехода на DataInOut (с <code>aether_data_out_t</code>/<code>aether_data_in_t</code> напрямую в сигнатурах, без builder_stream) в stream-части пока <b>нет</b> — <code>builder_stream</code> и <code>stream_commit</code> остаются обязательными аргументами.</p>
