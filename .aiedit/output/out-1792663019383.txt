<h3>Анализ stream-обработки в emitter.c</h3>
<p><b>Главный вывод:</b> C-генератор использует собственный тип <code>&lt;stream&gt;_t</code> (структура с полями <code>data/capacity/length</code>) для builder-параметров, а не напрямую <code>aether_data_out_t/in_t</code>. Однако внутри builder-методов создаётся <code>aether_data_out_t</code> поверх буфера stream для сериализации аргументов и вызывается обычный API-метод через <code>remote</code> с commit-функцией. Для nullable stream (<code>TestStream?</code>) требуется согласованность имени типа (без суффикса <code>?</code>) между объявлением, определением и диспетчером — тест <code>test_emitter_nullable_stream.sh</code> проверяет только успешную генерацию, но не компиляцию, что оставляет риск рассинхронизации.</p>

<b>1. Функции stream-builder'ов:</b><br/>
- <b>emit_stream_builder_declarations_for_api_ctx</b> (3987–4100): объявляет функции вида <code>aether_status_t &lt;stream&gt;_&lt;api&gt;_&lt;method&gt;(&lt;stream&gt;_t *builder_stream, ...)</code>.<br/>
- <b>emit_stream_builder_definitions_for_api_ctx</b> (4346–4578): реализует эти функции. Ключевой фрагмент (не-collapsible ветка):<br/>
<pre>aether_status_t &lt;stream&gt;_&lt;api&gt;_&lt;method&gt;(&lt;stream&gt;_t *builder_stream, ...) {
    // проверки
    size_t remaining = builder_stream->capacity - builder_stream->length;
    &lt;abbr&gt;_stream_commit_t commit = { &builder_stream->length, remaining };
    aether_data_out_t out;
    aether_data_out_init(&out, builder_stream->data + builder_stream->length, remaining);
    &lt;abbr&gt;_&lt;api&gt;_remote_t remote = { &commit, &lt;abbr&gt;_stream_commit, &out };
    return &lt;abbr&gt;_&lt;api&gt;_&lt;method&gt;(&remote, ...);
}</pre><br/>
- <b>emit_stream_commit_once_ctx</b> (4637–4699): генерирует тип <code>&lt;abbr&gt;_stream_commit_t</code> и статическую функцию <code>&lt;abbr&gt;_stream_commit</code>, которая увеличивает <code>*length</code> на переданное количество байт.
