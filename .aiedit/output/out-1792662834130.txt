<h4>1. Ключевые функции stream-обработки</h4>

<li><code>emit_stream_builder_declarations_for_api_ctx</code> (3987): генерирует прототипы builder-функций для каждого метода API, связанного со stream-типом. <h4>2. Stream в API-методах</h4>
<p>В <code>emit_api_source_ctx</code> (5834) обычные методы генерируются с сигнатурой:</p>
<pre>aether_status_t &lt;api_abbr&gt;_&lt;api_name&gt;_&lt;method_name&gt;(
    &lt;api_abbr&gt;_&lt;api_name&gt;_remote_t *api, ...)</pre>
<p>Внутри используется <code>api-&gt;out</code> (указатель на <code>aether_data_out_t</code>) для записи байтов. Stream-параметры в таких методах обрабатываются через <code>emit_serialize_param_ctx</code> (2441), который для stream-параметров проверяет <code>NULL</code>, валидность <code>length &lt;= capacity</code> и вызывает <code>emit_bytes_view_expression</code> для записи данных и длины.</p>
<p>Stream-специфичные builder-функции генерируются отдельным блоком (в <code>emit_all_stream_builder_declarations_ctx</code> / <code>definitions</code>). Они называются <code>&lt;stream_c_name&gt;_&lt;api_name&gt;_&lt;method_name&gt;</code> и принимают <code>builder_stream</code> вместо <code>remote_t</code>.</p>

<h4>3. Обычные методы и DataInOut</h4>
<p>Обычные методы используют <code>aether_data_out_t</code> через поле <code>out</code> в <code>remote_t</code>. Типовой код:</p>
<pre>aether_status_t csa_foo(csa_remote_t *api) {
    if (api == NULL || api-&gt;send == NULL || api-&gt;out == NULL) return AETHER_ERR_ARGUMENT;
    aether_data_out_t *out = api-&gt;out;
    if (!aether_data_out_write_byte(out, 0x01)) return AETHER_ERR_OVERFLOW;
    ...
    return api-&gt;send(api-&gt;send_ctx, api-&gt;out-&gt;data, api-&gt;out-&gt;pos);
}</pre>
<p>Это соответствует DataInOut-подходу: данные пишутся в буфер <code>out</code>, затем отправляются.</p>

<li><code>stream_builder</code> — встречается в комментариях и как часть имён функций.</li>
<li><code>builder_stream</code> — имя параметра в builder-функциях.</li>

<h4>Анализ и выводы</h4>
<ul>
<li><b>Что работает:</b> builder-функции генерируются корректно, используют <code>aether_data_out_t</code> и commit-механизм для последовательной записи. Обычные API-методы используют тот же DataInOut подход. Stream-параметры корректно сериализуются (проверки NULL, запись view) и десериализуются через <code>aether_data_in_read_view</code>.</li>
<li><b>Что выглядит недоделанным:</b> в <code>emit_serialize_param_ctx</code> обработка stream-параметра идёт до проверки nullable. Для nullable stream-параметра (<code>TestStream?</code>) не генерируется отдельный <code>if (param != NULL)</code> блок — код будет пытаться разыменовать NULL, если параметр пропущен. Возможно, это обрабатывается маской nullable на уровне метода, но прямого учёта nullable в stream-ветке нет.</li>
<li>В builder-функциях не проверяется, что <code>builder_stream-&gt;data</code> не NULL при capacity &gt; 0 (для не-collapsible есть проверка, но в collapsible — тоже есть). В целом проверки есть.</li>
<li>Возможно, stream-типы и builder-функции следовало бы вынести в отдельный модуль, но сейчас они генерируются в общем потоке API.</li>
</ul>
